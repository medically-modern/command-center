01

Start here. Always.

Before anything else

Open the patient on Monday. Read the actual columns.

This one look splits every problem in half. Do it before you ask anyone anything.

Board is wrong

Something wrote badly, or nothing wrote. Now open the Activity Log — it shows who changed what, and when.

Board is right

Data's fine. The app is filtering or counting it wrong. Go to section 03.

Rule these out first — they are not bugs

Numbers lag. Lists refresh every 30 seconds. Counts every 60. Wait a minute before believing a mismatch.

Blank screen? Reload once. A tab left open across a release does this.

FAX says "Done!" with faxes waiting? Once it hits zero it stays Done until midnight. Use the Fax Inbox page.

02

Why a patient disappears

Three gates. A patient must pass all three to show up in someone's list.

GATE 1

Which queue

Board and group get you most of the way. Three places split further:

Medical Evaluation Splits by Stage Advancer, matched exactly: Evaluate MN, Send Request, Confirm Receipt, Chase Clinicals, Doctor Appointment.
Chase Clinicals Clinicals Method. Parachute or Email → Email & Parachute. Everything else, blank included → Fax.
Profile Send Off Already In System = Yes gets its own queue. Everything else in 1. Intake is Verified Referrals.
If you were told otherwise — this changed 10 Aug

Referral Type and Referral Source no longer route anybody. Patient Intake is now the DTC form's own two groups and nothing else. A "Patient" referral type does not move someone there any more.

src/lib/profile/referralSplit.ts · src/hooks/useRoleCounts.ts

GATE 2

Due today

There is no single rule. This is where most confusion comes from — check which column controls the stage you're in.

Evaluate · Send Request · Confirm Receipt · Chase · Doctor Appts Next Action Date. Hidden only when the date is in the future. Blank, today, past = due.
Benefits · Submit Auth Status AND date together. Hidden when status is Follow Up and the date is blank or future. Once the date arrives, they're due again.
Auth Outstanding · DVS Date only. Status is ignored completely. Blank date = due now.
Welcome Call · all three Profile queues Follow Up status. Hidden when it's Done.
Final Confirmation No rule at all. Only escalation removes anyone.
Scheduled Calls The clock. Drops off when the booked time passes, or if the booking is Canceled.

src/hooks/useRoleCounts.ts

GATE 3

Escalated

Escalating removes a patient from the rep's list and count and puts them in a manager column. That's the point of it. Two rungs:

Manager Escalation Required → Manager Intervention column.
Final Escalation Required → Final Decisions column. On Medical Evaluation this means a rep proposed the patient be marked stuck. It's a proposal, not a decision.

Only a manager sends someone back down. Doing so clears the escalation — that's what returns them to the rep.

Two exceptions worth knowing

DVS ignores escalation entirely. Escalated patients stay in that queue and that count.

Proposed-stuck on Medical Evaluation is counted nowhere — not in the active count, not in the escalated count. Reach them through the manager views.

src/hooks/useRoleCounts.ts

The failure this system is prone to

A patient can end up in no queue at all, and nothing will tell you. No error. No warning. No red number. They just stop being worked.

So "nothing looks wrong" proves nothing. If a patient feels stuck, report it even if you can't point at anything.

03

What the save message meant

The toast after a save is the single most useful clue in the app. There are three and they mean completely different things.

"… — confirmed in Monday"

Done and durable. Everything wrote and was read back. Nothing to do.

"Data in server — Monday confirmation still pending"

It will run. The job is queued on the server and is not lost.

Do NOT save again. Repeating it writes twice. Wait, then check the board.

"Save failed — nothing was written"

The patient did not advance. Retry. If it fails twice, report it with the item link and the time.

No toast at all?

Some smaller actions — logging an attempt, marking complete, the Subscription save — write more directly and confirm less. If you saw no message, check the board.

Why a save can refuse to advance someone

Useful when a rep insists they saved and the patient didn't move.

04

Find your symptom

Colour on the left = who fixes it. Skim the bold headings.

Patient is missing or in the wrong place

Patient vanished from a queue

Board data

Check Escalation first. If it's set, they're in a manager column — working as designed.

Not escalated? Check the due-rule column for that stage (Gate 2).

Patient is in no queue and no count

App rules

The Stage Advancer holds a value no rule matches. Every filter skips them silently.

Report it with the item link. This never fixes itself.

Right board, wrong queue

Board data

Check the splitter: Clinicals Method for Chase, Already In System for Profile.

A blank Clinicals Method routes to Fax deliberately, so nobody falls through.

Escalated, but in no manager column

App rules

They're invisible to everyone — the rep can't see them and no manager chart lists them.

Highest-priority bug in the system. Report immediately.

Saved it and it didn't stick

Rep saved it, board is blank

The save

Ask what the toast said (section 03). Then read the item's Activity Log.

No write logged = it never reached Monday. Written then changed = an automation or bot overwrote it.

Saved, but the patient never advanced

Board setup

Did the Stage Advancer actually change on the item?

No = the save aborted on purpose; retry. Yes = the Monday automation is broken.

One column is blank for every patient

Board setup

That column was deleted and recreated. It got a new hidden ID and the app is still asking for the old one.

Renaming a column is safe. Deleting and recreating one silently breaks it.

Duplicate-looking status labels appeared

Board setup

A label was renamed. Some writes match exact text, so Monday made a new label instead of failing.

Flag status-label renames before they happen.

Numbers don't agree

A list and its own count disagree

Not a bug

Lists refresh at 30 seconds, counts at 60. Wait a minute and reload.

Only report it if it survives that.

Role bar and Oversight chart disagree

App rules

The same rule lives in five places and one copy drifted (section 05).

Report every number you can see — bar, list, chart. The pattern identifies which one.

Burndown says a role is "not connected"

App rules

The morning snapshot has no entry for that role. It says "not connected" rather than a misleading zero — that part is deliberate.

FAX bar says "Done!" but faxes are waiting

Not a bug

Once the count hits zero it stays "Done!" until midnight, even as new faxes arrive.

Work from the Fax Inbox page instead of the bar.

Outside systems

Eligibility results stay blank

A bot

The app never writes those columns — a separate service does.

First check Name, DOB, insurance and Member ID were filled in before the check ran. If they weren't, it never fired.

DVS or claims not progressing

A bot

DVS is automatic and that page is a read-only monitor.

Supplies and pump claims are separate columns. A pump problem won't show in the supplies one.

Fax or email didn't send

A bot

Sending never touches Monday. Check the address or fax number on the item, and that the person is signed in.

Incoming calls stopped appearing

A bot

Check that person's ring setting: all, list, or off.

Narrowing it silences their screen only — it can never make a call unanswerable by someone else.

Blank screen or a page won't load

Not a bug

Reload once. A tab left open across a release does this. Report it only if reloading doesn't fix it.

05

Why a fix sometimes half-works

The pattern behind most count bugs

One rule is written in five separate places.

Change four of the five and nothing errors — you just get a list that's right and a count that's wrong.

What this means for you: when reporting a counting problem, name every place you saw it. "Bar says 12, list shows 9, chart says 14" identifies which copy drifted. "The count is wrong" doesn't.

06

How to report it

Copy this. The last three lines are what make it fixable same-day.

Patient: [name + Monday item link] Where: [page, chart or role bar] Expected: [what you thought would happen] Saw: [what actually happened] When: [date + rough time] Toast: [exact words, if any] On the board: [what the columns say right now] Also seen in: [any other count or chart that disagrees]

Where to look yourself

Activity Log on the Monday item — who changed what, when. Needs no special access and answers most questions.

Where to escalate

Pipeline Oversight for escalated patients. Beyond that — the audit log and health checks — ask Josh.

Words you'll hear
Stage Advancer
The one column Monday's automations watch. Changing it moves the patient. The app writes it last.
Next Action Date
Controls the Medical Evaluation queue. Only a future date hides someone.
Follow Up / Follow Up Date
The snooze on the other boards. Which one controls the queue depends on the stage — see Gate 2.
Escalation
Moves a patient from the rep to a manager column. DVS ignores it.
Propose Stuck
A rep asking that a patient leave the pipeline. A proposal — a manager decides.
Gateway
The server the app talks to Monday through. Holds the credentials, logs every request.
Baseline
The morning count snapshot the burndown compares against.
Stedi
The eligibility check. A separate service runs it and writes the results.
DVS
Automatic Medicaid verification. Bot-run; the page just watches.
Parachute
An outside source for clinical documents. Shares a queue with Email.
Masheke / Samantha
Old internal nicknames for the Medical Evaluation and Insurance boards.
How the pieces fit together

The app has no patient database. Every fact on screen is a Monday column, read moments ago. Four things write to those columns — the app, Monday's automations, the Railway bots, and anyone editing the board by hand.

Every rule here was read from the code on 11 August 2026 (commit b5a5f8f). Rules change — if something stops matching what you see, that's worth reporting too.
