### 5.13c Each person's own RingCentral line in Command Center (Sep 2026)
Josh, 2026-09-30: *"we want someone to call, everyone has their own sign in to void the 5 user
katie sign in cap and everyone gets rung in cc"*. This is §5.13b's Route A, built without the call
queue it planned (see "What the RingCentral side is" below).

**The problem.** Every browser provisioned its softphone with the gateway's one JWT, which belongs
to Katie's extension (ext 2), so the whole team shared her **five** SIP registrations (§5.13b). The
RingCentral desktop app signed in as Katie spent the same five, which is the throttling the team
kept hitting ("line full").

**What the RingCentral side is (set up 2026-09-30, in the admin portal, no code).**
- Staff users that already existed: Janelle (ext 7), Masani (ext 8), Victor (ext 13), each on
  RingEX with a Digital Line attached to the RingCentral App. No seats were bought.
- **Katie's line rings them directly**: Users → Katie Tyler → Phone → Incoming call rules →
  Incoming calls → Ring settings → *Add number or coworker* → each of them (ring all together).
  Katie's greeting, Classical connecting music and voicemail are unchanged, and unanswered calls
  still land in **Katie's** voicemail (verified with a test call).
- ⚠️ **The call-queue attempt failed and is switched off.** A custom rule on Katie ("Main line to Temp
  Ring All", *calls to (347) 503-7148 → queue ext 15*) sent a real call straight to voicemail: the
  queue treats every device signed in as Katie as ONE agent, so one rep on a call made "Katie" busy,
  and the other members were still signed in as Katie, so there was nobody available. Katie's line
  has call waiting on, and the queue took that away. The rule is **off** and the queue **Temp Ring
  All** (ext 15) is unused. The eight phone-tree queues (ext 4, 5, 6, 9–12, 14) were never touched.
- ⚠️ **Automatic recording is per user.** Only Corey, Katie and Stephen were being recorded; Janelle,
  Masani and Victor were added on 2026-09-30 (Phone System → Company → Sites → Main Site → Call
  recording → Automatic → Extensions to Record). A call Victor answered before that has no recording.

**What the code does.**
- **Gateway, `services/monday-gateway/rcUserAuth.mjs`** (pure half: `rcUserAuthRules.mjs`):
  `POST /rc/user/connect` (signed in) returns RingCentral's sign-in address, with a **signed, 15-minute
  `state`** that carries who clicked. `GET /rc/user/callback` exchanges the code, **refuses a login
  from any other RingCentral account** (compared with the JWT's account, failing closed), and stores
  the grant in `rc_user_links` on the **messaging** Postgres, keyed by the Google email.
  `GET /rc/user/status` and `POST /rc/user/disconnect` complete it.
- **`/messaging/sip-provision`** asks `provisionOwnLine(who)` first. A connected person gets THEIR
  extension's SIP credentials (`mmLine: "own"`); everybody else gets the shared line exactly as before
  (`mmLine: "shared"`). The sip-provision floor still runs first (`sipProvisionFloor.test.mjs`).
- **SPA, `lib/softphone/rcLine.ts`**: the status, read once per page load and again after a
  connect, disconnect or sign-in, **never on a timer**. Other tabs hear about a change through the
  `mm-rc-line-changed` storage key. `phoneLine(answerer, state)` is the one gate, used by both
  `IncomingCallHost` and `useCallStatus`: connected → rung on `own`, assigned or not; an answerer who
  hasn't connected → `shared`; anyone else → not rung.
- **`softphone.ts`** takes `setLine` before `setEnabled`, remembers which line the live registration
  is on (`wpLine`), and re-registers on a change, but never under a live call (`endActive` reconciles
  afterwards). The sipInfo cache (`registration.ts`) is keyed by line as well as email; entries from
  before this change count as `shared`.
- **Where people click:** settings gear → Calls → *Connect my own RingCentral line…* (the redesign
  shell has no home badge), or the home badge's *Connect RingCentral to take calls* / *Use my own
  line* on the old layout. *Disconnect my RingCentral line* is in the same menu and is disabled during
  a call. A successful return toasts "RingCentral connected".
- **`inboundCalls.mjs`** adds every connected person's own DIDs to the self-number list, so a rep
  dialling out on their own extension does not pop a card on everybody's screen.

**Rules that are correctness, not style (pinned by `rcUserAuthRules.test.mjs` and `rcLine.test.ts`):**
- ⚠️ **A SECOND RingCentral app.** The developer console allows ONE auth flow per app, and the
  gateway's app is JWT. Texting, faxing, the call webhook and every archive sign in with it, so
  switching that app to the authorization-code flow would take all of them down. The per-person app is
  `RC_USER_CLIENT_ID` / `RC_USER_CLIENT_SECRET` (3-legged authorization code, refresh tokens on,
  scopes VoIP Calling + Read Accounts, redirect `https://monday-gateway-production.up.railway.app/rc/user/callback`).
  Until those two variables are set on `cmd ctr server`, status says `configured: false`, no Connect
  button shows anywhere, and nothing changes.
- ⚠️ **`/rc/user/*` is registered BEFORE `registerRingCentral`.** Its `app.all(/^\/rc\/.+/)` proxy would
  otherwise answer the callback 403, and the callback's address is registered with RingCentral, so the
  path cannot move.
- ⚠️ **Refresh tokens are sealed (AES-256-GCM) before they touch Postgres**, and access tokens stay in
  memory. The key is `RC_USER_TOKEN_KEY`, or HKDF of `PHONE_HMAC_PEPPER` under its own label (so it
  needs no new secret). **Rotating the pepper therefore disconnects everybody**; they connect again.
- ⚠️ **A dead grant is NOT put back on Katie's line.** Provisioning answers 409 "connect again" and the
  badge turns red with *Reconnect*. Falling back would quietly spend one of her five, which is the
  problem this exists to end.
- ⚠️ **RingCentral rotates the refresh token on every refresh**, so refreshes are one at a time per
  person. A keep-alive every 6 hours refreshes any grant with under 4 days left, because the browser
  caches its SIP credentials for 7 days and may not ask the gateway for anything all week.
- ⚠️ **Nothing registers until the status is in** (`phoneLine`): otherwise a connected answerer would
  first register on the shared line and spend one of Katie's five for the second it takes to find out.

**Open, known on 2026-09-30:**
- **Outbound caller ID.** The softphone dials with `mmPhoneNumber()` (the main line, Katie's direct
  number). Whether RingCentral lets another user's extension present that number is unverified. If a
  test call from a connected rep shows their own number, set each user's outbound caller ID to the
  company number in the admin portal (the company number rings ext 2, so a callback still reaches
  everyone).
- **Where a coworker-answered call's recording lands.** The archive, call history and Communications
  Inbox read **Katie's** call log only (`callArchive.mjs` `/account/~/extension/~/call-log`). A call
  Victor answered through Katie's ring settings IS in Katie's log as a normal answered call, not
  missed (verified). Whether its **recording** is attached there, or only in Victor's log, was not
  yet verified when this shipped. If it is only in Victor's, those three must read the account-wide
  log.
- `/access`'s "Answer calls in the browser (N of 5)" still counts only the shared line. A connected
  person needs no assignment, and the phone-presence board does not yet say which line a browser is on.
