### 5.59 Profile order rules (caps, max frequency, stock flag) and the Comms list divider (Oct 2026)
Josh's "10/1/26: Command Center Changes", plus his answers the same day. **No board change; app only.**

> *When changing infusion set on profile view, flag if the new infusion set selected is not in stock
> as a warning · Build in infusion set/cartridge max limits … when editing the number — Anthem = 9,
> Horizon = 9, Aetna = 4 → can do 75 days, everyone else is 3 · Rules for changing Frequency in
> profile page — Medicaid and Fidelis → can do 60-days, Aetna → can do 75-days, all else → 90 days ·
> Sliding feature on comms tab (like we have between middle and right panel, let's also have between
> middle and left panel).* Then: *"for commercial plans"*.

Asked directly, and answered (2026-10-01):
1. **"Aetna" means Aetna COMMERCIAL** — for the cap of 4 AND the 75-day option, everywhere in the app.
2. **Each payer's number is the MAXIMUM frequency** — Medicaid group: 30 or 60; Aetna Commercial: 30,
   60 or 75; everyone else: 30, 60 or 90.
3. **The 60-day group is the PRIMARY Insurance exactly "Medicaid" or "Fidelis Low-Cost" — "that's
   it"** — not Fidelis Medicaid, United Medicaid or Anthem BCBS Medicaid (JLJ), and a Medicaid
   SECONDARY does not count.

**Where.** The patient screen's Subscription **Profile** tab, the *Order details* card
(`components/patient/SubscriptionCards.tsx` `OrderDetailsCard`). The rules live in the shared
modules, not the card.

**1. The cap on Inf. qty 1, Inf. qty 2 and Cartridges qty** — `lib/shared/infusionCap.ts`, the SAME
table Welcome Call and Final Confirm use (§5.32g): Anthem BCBS Commercial 9 · Horizon 9 · **Aetna
Commercial 4** · everyone else 3. The labels read *"Inf. qty 1 · max 4"* for an editor. A typed number
above the cap is **refused** (the box keeps its value) with *"Over the cap — Aetna Commercial caps
infusion sets and cartridges at 4 per order."* — Welcome Call's 2026-09-17 enforce-don't-just-render
rule. The sets' **total** over the cap is flagged amber under the card, as C31 does, including a value
the board already holds (measured: one Aetna Commercial subscriber carries 6).
⚠️ **The payer alone.** The Subscription board's *Referral* dropdown is rep names — no CareCentrix label —
and every CareCentrix patient is Horizon (already 9, §5.32g), so the referral route is not read here.
⚠️⚠️ **`/aetna/i` → `/aetna.*commercial/i`, app-wide** (`infusionCap.PAYER_CAP_RULES` and
`payerRules.payerAllows75Days`). So Welcome Call's cap note and 75-day option, and Final Confirm's C31,
follow. Measured first: **no Aetna Medicare row** on the Welcome Call board (8 rows, max qty 3) or the
Subscription board orders above 3 or runs 75 days — nobody moves.

**2. The max Frequency** — `payerRules.profileFrequencyMaxDays / profileFrequencyDays /
profileFrequencyRefusal`. Options are 30, 60 and the payer's max (75 only for Aetna Commercial, 90 for
everyone but the 60 and 75 payers). ⚠️ **The board's saved value is always shown and never rewritten**:
measured on the Subscription board's active group the day this shipped — Medicaid 288 on 60 · 2 on 90;
**Fidelis Low-Cost 66 on 90** · 2 on 60. Those 68 profiles keep their 90 and show a muted *"Fidelis
Low-Cost goes up to 60 days. Saved before this rule — it stays until it's changed."*; a NEW pick above
the max can't be made, and a rep edit that falls outside the rule (a payer corrected on the same card)
turns the line amber: *"… Pick 30, 60 days."*
⚠️ **This is the profile's rule, not Welcome Call's.** Welcome Call's supply-length options
(`supplyLengthOptions`: 30/60/90 for all, +75 for Aetna Commercial) and its Medicaid default
(`isMedicaidPlan`, which reads the secondary too) are unchanged apart from the Aetna Commercial
narrowing — Josh's list named the profile page.

**3. The stock flag on a newly picked infusion set** — `SetStockFlag` under *Infusion set 1/2*, only when
the picked label differs from the board's (`saved` prop from `SubscriptionView`). It reuses Welcome
Call's `useInfusionStock` (one module-scope read of the Cardinal SKU Tracker, 30-min TTL) and
`stockVerdict` (§5.31b: STATUS decides — a Backordered set with 220 on hand is still *"Not in stock"*;
no tracker row is UNKNOWN, never in stock). Not in stock → amber *"Not in stock — …"*; available →
muted *"In stock at Cardinal · 1,715 in stock"*; low → muted *"Low stock …"*.
⚠️ Its own component so the tracker is read only once a set is actually CHANGED — mounting the hook in
the card would read it for every profile anybody opens.

**4. The Comms list divider** — `AssignedPatientsPage`, between the list (left) and the thread
(middle), beside the existing thread | profile handle (§5.30k). `PaneResizer` gained `edge="right"` (a
LEFT pane's right edge: drag right / → to widen) and a `reservePx` FUNCTION read at the press. The
handle sits in a zero-width flex item on the boundary, so the list pane's own classes — pinned by
`inboxWiring.test.ts` — are untouched; a dragged width is an inline style over them. Remembered per
browser (`cc.pane.commsHubList`); double-click resets; floor 320px (`w-80`, today's narrowest list).
⚠️⚠️ **Each dragged pane leaves room for the OTHER, so the thread keeps ~300px:** the profile's reserve
is today's 760 until the list is dragged, then `360 + list px`; the list's is `360px + (profile px |
clamp(23.5rem,36%,34rem))`, as CSS (`paneWidthCssExpr`) and, for the drag, the same clamp computed by
hand. ⚠️ Not `getComputedStyle(…).minWidth` — a percentage clamp computes to the expression, which
parses as NaN: measured, the list then REMEMBERED 1080px while 562px was drawn.
Measured in a browser: 1440 inbox off 320 → 470 → max 562 (thread 296); inbox on 400 → max 562; 1100
inbox on 320 → max 344 (thread 296); both panes dragged to max at 1440 — list 400 · thread 296 ·
profile 680; double-click back to 320/400; no horizontal scroll.

**Rendered** (throwaway harness, fake data, not committed): the card at ~440px and ~340px (its width in
