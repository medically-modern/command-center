### 5.47d Who picked up — the answering extension on every inbound call (Sep 2026)
Josh, 2026-09-30, the day the forwarded-lines setup went live (a call to the shared line now rings
several people's own RingCentral extensions at once): *"we need to save who picked up into the
database so the calls are saved with his name and ext number … in communications i want it to show
when we pick up who picked up"* — then narrowed: *"only which ext picked up"*, **inbound only**,
because *"outgoing calls will all say katie"*.

**What RingCentral says, measured on a real call that day** (Detailed view of the shared line's
call log): a **master** leg (`Accepted`, `to` = the line's own extension, ext 2) and one **fan-out**
leg per extension it rang, all at the same second: ext 2, 13, 8 and 7, each `Stopped` or
`IP Phone Offline` except the one that answered, **`Call connected`**, whose
`to.extensionNumber` was **13**. The fan-out legs carry the extension NUMBER and no name, and the
recording hangs off that connected leg.
⚠️ **Why outbound is excluded:** every outbound call leaves from the ONE shared extension (§5.13b),
whose owner is ext 2, so RingCentral would name the same person on every one. Who pressed Call is
already recorded separately by the Command Center (`comms_dials`, §5.49) and shows as
*"We called · Katie"*; that is unchanged.

**Saved** — `call_archive.answered_ext` + `answered_name` (messaging pool, next to the call; staff,
not patient data). `callArchiveRules.answeredByOf(record, directory)`, in order:
1. a non-master leg that `Call connected` to a **User** extension → that extension (the longest if
   several — a transfer rings on);
2. ⚠️ a leg that connected to something that is NOT a person's extension (a forward to a cell, the
   old "Take it" of §5.13; an IVR menu; a queue) with no person's leg connected → **null**, never
   the line's own owner;
3. otherwise an answered call (`Accepted` / `Call connected`, no voicemail) was picked up on the
   line the log belongs to → the master leg's `to`, i.e. ext 2.
Null on outbound, missed and voicemail calls. ⚠️ Only **User** extensions count as "who": an IVR
or a department "connecting" is routing. With no directory the type is unknown and the extension is
taken as it stands.
**The name** comes from `GET /account/~/extension` (`rcDirectory.getExtensionDirectory`): cached six
hours, `background` tier, never throws; a failed read is retried after ten minutes, not every
capture tick. With no list the extension NUMBER is still saved, and the upsert
(`COALESCE(EXCLUDED…, call_archive…)`) fills the name in on a later scan and never blanks a known
value. `/calls/archive-health` reports `extensionDirectory` (a count and timestamps, never a name).
**Every write path** goes through `archiveCallRecords`, the one door into `call_archive` (the
minute-by-minute Communications capture, the hourly 2-day scan, and the daily 95-day deep pass), so
the deep pass fills in the last 95 days' inbound calls on its own.
⚠️ Calls answered on ext 2 itself read as ext 2's owner. That is literally which extension picked
up; nothing on RingCentral's side can say which person was holding ext 2. A call answered in the
Command Center browser is logged by RingCentral as OUTBOUND (§5.49 `markBrowserPickups`), so it
carries no answering extension at all.

**Shown** — the Communications timeline (`ItemTimeline`, the hub's item and the patient header's
Communications popup): under *"Answered call · 2:03"*, a line **"Picked up by Victor Guerra
(ext 13)"** (`timeline.answeredByLabel`; *"Picked up by ext 13"* when there is no name). Its own
line, deliberately: appended to the headline, the duration wrapped onto a line by itself at the
popup's width (rendered at 420 · 760 · 420 dark, 2026-09-30). `/calls/archive/query` returns
`answeredExt` / `answeredName` too, for other services.
⚠️ The timeline query selects the two columns only when they exist (`archivesPresent().answered`):
the archive adds them at boot, but not while it is switched off (`CALL_ARCHIVE_ENABLED=0`), and a
select of a missing column would take the whole timeline down.

**On the live inbound-call card too (Josh, 2026-10-02: *"when it says answered can we show who answered? Like victor
or janelle"*).** The card's "Answered" now reads **"Answered by Victor"** ("You answered" on your own screen). Not
from RingCentral: the live telephony events were not measured to name the answering extension (the gateway's
`/calls/health` line log, 2026-10-02, showed no extension legs on two inbound sessions), and the archive above only
learns it from the call LOG minutes later. Instead the **answering browser reports itself**: `softphone.ts` `doAnswer`,
inside `session.once("answered")` (so a failed answer names nobody), calls `reportAnswered` →
`POST /calls/answered { callId: <telephony session>, from }`. The gateway takes the person from the verified
sign-in (never the body), matches the call (`callRules.findAnsweredCall`: by session id, else the newest call from
that number in the last 2 minutes), sets `answeredBy`, broadcasts `call-update`, and writes a `call_events` row
`kind = 'pickup'`, `claimed_by` = the email. First report wins.
⚠️ **The report never ends a ringing call.** The session's own end event still writes the `end` row, which
Communications' pickup and missed-call logic read (`commsInbox.mjs`), and it now writes it as `answered` when
`answeredBy` is set (the stale sweep agrees). A call the end event already called `missed` is flipped to answered
in memory (the card); its `end` row stays. In the browser, `ringMerge` treats a call with `answeredBy` as answered
once no leg rings here, and `useInboundCalls` clears it on the usual 6-second linger.
Only browser answers are named; a call taken on a desk phone or the RingCentral app still reads "Answered".
