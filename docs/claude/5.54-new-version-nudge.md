### 5.54 The reload nudge — open tabs learn a newer build is live (Sep 2026)

Josh, 2026-09-28: *"yes add the reload nudge"* — after a day in which stale tabs bit three times.
**A deploy never reaches a tab that is already open**: the browser keeps executing whatever
JavaScript it loaded the day the tab was opened. `chunkReload.ts` (§9) heals only the case where
that breaks VISIBLY — a lazy navigation 404s on a replaced chunk. A tab that just sits on one page
runs old code indefinitely. That morning Katie's prod tab showed the forever-retrying registration
AND a "Hanging up…" overlay that never ended — both bugs whose fixes had been live for days (prod's
deployed bundle, `index-BHxd1vZ2.js`, was fetched and grepped: the 8s hang-up deadline was in it).
Her tab predated 2026-09-25.

**How it knows, with no build changes** (`lib/shared/buildVersion.ts`): Vite names the entry
script by content hash (`assets/index-<hash>.js`). The tab's own `<script>` tag says which one it
loaded (`runningEntry`); the deployed `index.html` says which one is current
(`fetchDeployedEntry`, from the app's own `BASE_URL`, so test compares with test and prod with
prod). Different ⇒ newer. ⚠️ **Both halves must be known** (`isNewerBuild`): a failed fetch, the
dev server (no hashed entry) or a malformed page is silence, never a nudge — one that fired on a
network blip would be ignored within a week, and then so would the real one.
⚠️ **The fetch is cache-busted twice**: `cache: "no-store"` for the browser and `?v=<now>` for the
Pages CDN (ten-minute max-age). Without both, a tab can be told "you're current" by a cached copy
of its own page.

⚠️⚠️ **THE BUILD MUST STAY DETERMINISTIC.** Measured 2026-09-28: two builds of unchanged source
produced the same entry (`index-B6vb6HvA.js` twice); `vite.config.ts` and `deploy.yml` stamp
nothing. So the weekday 07:00 UTC cron rebuild and the daily baseline/access commits
(runtime-fetched from `public/data`, never bundled) nudge nobody — only a code change does.
**Adding a `Date.now()`/commit-SHA `define` would nudge every tab every morning for nothing**;
`buildVersion.test.ts` fails the build on one.

**The banner** (`components/shared/NewVersionBanner.tsx`, mounted once in `App.tsx`, outside the
router): one 5-minute timer plus a check whenever the tab becomes visible (the moment a days-old tab
matters), floored at one fetch a minute. Static GitHub Pages fetch — no gateway, RingCentral or
Monday cost. Once a newer build is seen it stops asking.
- ⚠️ **It never reloads by itself.** An automatic reload would drop a live call (the audio is in the
  page, §5.13b) and throw away half-typed work. **Later** snoozes 30 minutes and then it comes back
  — the whole failure is a tab nobody reloads for days.
- ⚠️ **Reload is refused during a call** in this browser (`useSoftphone().call`), with the reason in
  the tooltip — reloading the tab that holds the phone ends the call for the patient.
- **Bottom-centre, by measurement.** Top-centre is the toasts' (and a lingering pill there would
  cover the redesign header's search box); top-right is the call cards; bottom-right is every stage
  page's primary action and the call overlay; bottom-left is the line-status notes and the
  sign-out/layout escape hatch (§5.39b). Measured on a real `--base` production build with
  `elementsFromPoint` sampling under the pill, on `/`, `/evaluate`, `/welcome-call`,
  `/care-coordinator`, `/access` at 1100 and 1440: **no fixed control under it anywhere**; at 1440 two
  SCROLLING elements (Care Coordinator's collapsible list header, an `/access` checkbox row) can pass
  beneath it, the same exposure every toast has, and it is dismissable. Tokens only (`bg-card`,
  `border-border`, `text-foreground`); rendered light and dark.

**The first sync after this ships is still manual:** a tab opened before the nudge existed cannot
run the nudge. Everyone closes and reopens their Command Center tabs once after that sync; from then
on the nudge carries every later deploy.

Tests: `buildVersion.test.ts` (13: the rules, the double cache-bust, the deterministic-build guard,
the wiring, one reload and it is a button) · `NewVersionBanner.test.tsx` (6: silent when unknown,
silent when current, offers when newer, **refused mid-call**, Later hides it, a failed check is
silence). The mid-call refusal and the both-halves-known rule were each verified to fail their
tests when removed.
