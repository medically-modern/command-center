### 5.58 Who to call on Benefits — CareCentrix for NJ/FL Blue, and BCBS FL's own modifiers (Oct 2026)
Brandon's handoff, 2026-10-01 (`HANDOFF-Josh-Who-To-Call.md`, checked by him against our paid claims on
Claims Board 18245429780): *"Call:" pills on the Benefits page so reps call the right party for each
check, and BCBS FL's own CareCentrix modifier set.* **Display only — no Monday column, no automation,
no write path changed.** It unblocks the item `BENEFITS_REDESIGN_TESTING.md` listed as "blocked on the
Anthem rulebook (D7)".

**Why.** CareCentrix runs the DME network AND the auths for Horizon (NJ) and Florida Blue (FL), not the
plan on the card. Asking Horizon whether we're in-network is what went wrong with Mark: Horizon
answered as if we billed Horizon directly.

⚠️⚠️ **THE ADDRESS DECIDES THE ROUTE — never the card, the Primary Insurance label, the member-ID
prefix or the referral source** (`lib/samantha/whoToCall.ts`). NJ or FL address → **CareCentrix**
(billed 11345 at POS 12); every other resolved state → **BlueCard** (the original July rule). A
Horizon member referred by their own doctor still routes via CareCentrix; so does an Anthem card with
an NJ address. Matches the claims tool (`claims-ui-tool/ANTHEM_SUBMISSION_RULES.md`). The two states
live in `CARECENTRIX_STATES` and nowhere else.

**When pills show — all three:** Primary Insurance ∈ `BCBS_FAMILY` (`lib/shared/pos.ts`), the address
resolves to a state (`resolveState`, never guessed — unresolved means no pills), and Member ID 1 is
not FEP (`/^R\d{8}$/i`, out of scope for v1). Every other payer: no pills, as before.

| Check | CareCentrix route (NJ, FL) | BlueCard route |
|---|---|---|
| 01 In-Network | CareCentrix | billed plan (Primary Insurance) |
| 02 Insurance Active | member's plan | member's plan |
| 03 DME Benefits | member's plan + "in-network benefits only" note | member's plan |
| Step 2 Auth | CareCentrix | member's plan |
| Step 2 Same or Similar | CareCentrix | billed plan |

Member's plan = Stedi Home Plan (`homePlan`, `dropdown_mm5ex8wx`), else Primary Insurance. BlueCard
**collapses** to one plan when home and billed share a first word (`authHomePlan`'s compare); the
CareCentrix route never collapses. Chip colours, one meaning everywhere: **mint** = our side (billed
plan or CareCentrix), **dark MM-teal** = the member's own plan when it's a different party. No phone
numbers anywhere — a payer phone directory is a separate project.

**Where it shows.** `BenefitsPanel`: a `Call:` chip under each check's Yes/No row, the DME note under
Check 03, and `Suggestion:` chips on the right of the step-2 header (one chip when Auth and SoS are the
same party, else `Auth → …` + `SoS → …`). Chip component: `components/samantha/CallChip.tsx`; styles
`.sugg-chip2` / `.uc-pill` / `.head-pills` in `benefitsRedesign.css`.
- ⚠️ The handoff's CSS used `var(--foreground)`; that token is an HSL TRIPLET in `index.css`, so it is
  `--bnr-foreground` / `--bnr-muted-foreground` here. Dark `--mm-teal` is a LIGHT teal, so the member
  chip takes dark text in dark mode — and so, since 2026-10-01, does the Home Plan box's **HANDLES
  AUTHS** tag (`.sbox.auth-plan .auth-tag`), the same white-on-teal pattern, which was unreadable in
  dark mode before. Measured: light `#fff` on `oklch(0.36 0.04 200)`; dark `oklch(0.145 0.012 255)` on
  `oklch(0.84 0.05 200)`.
- **Found by rendering:** the in-network note made the DME card taller, and `.uc-grid .seg{margin-top:auto}`
  pushed the other two cards' Yes/No rows lower. With pills (`.uc-grid.with-pills`, ≥961px) the cards
  share row tracks by `subgrid`, so the buttons and pills line up. Opt-in, so a patient without pills
  renders exactly as before. The step-2 header (`.step-head.has-pills`) wraps so the chips drop under
  the title at 1100 instead of squeezing it.

**Part B — BCBS FL modifiers** (`submitAuthRules.ts` `"bcbs-fl"`). BCBS FL bills **CareCentrix 11345 at
POS 12** with its OWN set: **A4230 NU · A4232 NU SC · A4239 NU · E2103 NU · E0784 NU SQ**, label
"BCBS FL via CareCentrix 11345". Until 2026-10-01 the route spread Anthem 803's supply lines with only
the pump overridden. It is NOT the Horizon CareCentrix table (A4230 there is NU SC). Only those five
codes: BCBS FL always bills A4230/A4232, so A4231/A4224/A4225 fall through to the defaults.
`modifierRoute()` still keys off the payer NAME (re-keying it off the address state is a separate
item), and the exact `"BCBS FL"` match stays before the Anthem regex. Hand-synced with
claims-ui-tool's BCBS FL table — update both.
