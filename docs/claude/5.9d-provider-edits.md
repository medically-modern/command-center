### 5.9d Provider edits on Medical Evaluation — Save provider, and a corrected fax reaching the send (Sep 2026)
Two reports on 2026-09-29: *"I updated the fax number for [a patient]'s provider in Confirm Receipt
and I can't send the fax again"* and *"I obtained new provider details for a patient. I'm not easily
seeing where I can update this information … from Send Request stage."* **No board change; app only.**
Files: `lib/masheke/doctorEdits.ts` (+ tests), `lib/masheke/mondayApi.ts` (`saveDoctorEdits`,
`buildDoctorWriteTasks`), `lib/shared/faxAddress.ts` (`faxEditToColumnValue`),
`components/masheke/SendRequestHeaderCard.tsx`, `mmKit.DoctorEditGrid`, `SendRequestPanel`'s composer,
`ConfirmReceiptPanel`; `components/masheke/providerEdit.test.tsx`.

**What the board showed (read live 2026-09-29).** The item was still on Stage Advancer **Send
Request**, not Confirm Receipt. Its Doctor Fax was **the doctor's phone number** (`<phone>@rcfax.com`),
the rep's Sep 25 note read *"Bad Fax — attempted multiple times"*, and the Doctor Fax column had
**never changed**: no corrected number had reached Monday. Four separate defects were behind that.

⚠️⚠️ **A FAX TYPED AS A NUMBER WAS NEVER SAVED.** Doctor Fax (`email_mm1xdzcj`) is an EMAIL column
holding `<digits>@rcfax.com`. The Edit grid is a plain text box, so a rep types `(215) 555-0100`;
`buildDoctorWriteTasks` handed that to `writeEmail`, and `planEmailWrite` **skips** a non-address
silently (it is built to never clear a column it can't read — `emailCell.ts`). So every advance
"saved" the provider and left the old fax on the board. The fax writer now goes through
`faxEditToColumnValue`: a value with a digit becomes `<digits>@rcfax.com`. ⚠️ A value with **no**
digit is passed through as typed, **never** through `toFaxAddress`, which returns `""` for it — and
`""` CLEARS the column, so a stray "n/a" would delete the fax it was typed over.

⚠️⚠️ **EDITS REACHED MONDAY ONLY ON THE ADVANCE.** The grid wrote to the page's local overlay;
Send Request wrote it on **Request Sent**, Confirm Receipt on **Save Attempt**, Chase on a saved
attempt, and **Doctor Appointments never** (its panel has no doctor writer). The page's **Save**
button is `saveOverlay`, which keeps the overlay **in this browser only**, and the hint beside the
grid said it saved to Monday. Worse: **DocExport builds the script from the BOARD**, so a rep who
entered a new provider and pressed Regenerate got a script with the OLD provider on it.
**Save provider to Monday** now sits in the grid (`saveDoctorEdits`). It writes only the fields
touched since the last save, one at a time, and clinic last, because clinic is the writer that can
refuse (a label the board doesn't have). The advance-time writes are unchanged. Anything left
unsaved is still written there, and the hints now say which press does it.
- ⚠️ **Checked before the first write** (`unsavableDoctorFields`): the phone and email writers skip
  what they can't parse rather than throw, so a 9-digit phone would "save" green having written
  nothing (the DVS page's `unwritableDoctorFields` lesson). The fax is held to the **deliverable**
  shape (`isFaxAddress`), not merely "an address": a truncated number would save as
  `215555010@rcfax.com` and a fax to it goes nowhere. A blank is a deliberate clear and passes.
- ⚠️ **Not a verified send (§5.2).** No stage advancer is touched. The six doctor columns DO each
  carry a board automation — *"When column changes, send a webhook"* (ids `592572629` … `592572815`,
  the Doctor Database sync, §8's `doctor-sync-webhook`) — and they fired on the advance-time writes
  before this too. Only the moment changed, not what is written.
- ⚠️ **A draft is keyed by patient** (`drafts[patient.id]`). The four pages don't key the card, so
  a single draft would ride along to the next patient and Save would write it onto them (§9). A save
  that lands after a switch only touches the overlay when the same patient is still open and the box
  hasn't changed since.
- Clinic stays **strict** (`writeDropdownLabels` without `create_labels_if_missing`), as it was on
  the advance: a free-typed clinic would create near-duplicate labels (§9). The refusal names the
  field ("Clinic Name: …"), and the fields before it are already saved.

⚠️ **THE EDITOR WAS TWO CLICKS DEEP.** "Show details" (muted text), then a small **Edit** toggle
inside the drawer. **Edit provider** now sits beside "Show details" and opens both. It appears only
where the page passes `onDoctorEdit`: Send Request, Confirm Receipt, Chase Clinicals and Doctor
Appointments. The patient screen (`/patient/:id`) still has **no** provider editor. Its stage panels
are read-only by design (§5.39c2), and the way in is the panel's **Open** link to the stage page.

⚠️ **SEND REQUEST'S "TO" BOX DIDN'T FOLLOW THE CORRECTION.** `SendRequestComposer` seeds `recipients`
from the doctor's contact **once**, at mount. A fax corrected in the header therefore never reached
the To box, and the send went back to the bad number. `followDoctorContact` now replaces the
prefilled entry **in place** when the doctor's value changes. It never touches an address the rep
added by hand, and it stops following once the rep removes the prefilled entry. Addresses are
compared as fax addresses, so `(215) 555-0100` and `2155550100@rcfax.com` are one recipient and
never two faxes to the same office.

⚠️ **CONFIRM RECEIPT LOCKED RE-SEND AFTER ONE PRESS.** The Not Confirmed box's button went to
"Re-sent" and stayed disabled for the rest of the attempt (`faxResent`), so a rep who re-sent,
learned the number was wrong and typed the right one could not send to it. A change of recipient now
clears `faxResent` and the "Re-sent just now" chip. That earlier re-send went to a number that is no
longer on screen.

**Rendered before shipping** (§5.30d's rule), in a harness around the real card, at 1440, 1100,
1440 dark and 390. There is no horizontal overflow, and the Save button's disabled→enabled colour
comes from the `--mm-green` token in both themes. (A first screenshot showed it pale. That was the
colour transition caught mid-way, not a missing token.)

**Keep-in-agreement:** `doctorEdits.DOCTOR_EDIT_FIELDS` ⇄ `mondayApi.DOCTOR_FIELD_WRITERS` (typed as
a `Record` over the fields, so a field with no writer fails the typecheck) ⇄ `mmKit.DoctorEditGrid`'s
six inputs · `unsavableDoctorFields` ⇄ `shared/phoneCell` / `shared/emailCell` / `shared/faxAddress`,
never a second shape test · the four pages' `editHint` ⇄ which press actually writes on that page.
