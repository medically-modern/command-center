Build notes — what came from where, and every change I made

What this is

The Command Center /profile page (design system, Stedi results grid, insurance suggestion engine, doctor DB + Parachute, patients sidebar, referral drawer) rearranged to function like Corey's PROFIL2 — two panes, right one locked until you advance on the left. CSS is a verbatim port of src/pages/profile/redesign.css so it matches the live page pixel-for-pixel.

Corey's flow, replicated

  • Left = Patient Info. Collection, right = Patient Profile Clean-Up, blurred + locked behind an overlay until Advance to Profile Clean-Up.
  • Attempt badge increments on each logged call attempt.
  • Auto-tags (Hypoglycemic episodes, Pediatric <18) plus event tags added by Start insurance follow-up and Escalate.
  • Conditional reveals: reason → Cost & coverage card; product category → device blocks; Provided via → card photo; General Insurance = Medicare A&B / Medicaid → State; proceed preference → call slot.
  • Three-way left decision: Advance / Insufficient — log call / Escalate (with reason + notes).
  • Benefits check on the left; Today's / 3-month / 6-month order estimates, gated on months remaining in the calendar year.

Structural changes I had to make

  • General Insurance vs Primary Insurance split. Corey's mockup had one "Primary insurance" dropdown on the left. These are two different columns: color_mm24ap4j General Insurance + text_mm4t8gbq Member ID are what the patient told us and what Stedi reads; color_mm1xg10n Primary Insurance + text_mm1x2qk2 Member ID 1 are the verified/derived answer. Left pane now holds General Insurance + Member ID; the right pane holds Primary + Member ID 1 + Secondary + Member ID 2 with the suggestion engine. Without this the benefits check has nothing to run against.
  • Right pane is 4 steps, not 3. Verified Insurance was added as step 1 to give the suggestion engine a home. Serving → Provider → Ready to Send Off follow as Corey had them.
  • Benefits check is async. Corey's version popped an instant modal. Stedi actually writes results back one column at a time over 15–25s with a ~10s settle, so this shows the real running state and then reveals the full grid at once. (Shortened in the prototype so you're not waiting 30s per click.)
  • Referral email + files are rail cards at the top of the left pane, matching the live page: Referral Type / Referral Source shown read-only with a Show referral email / updates toggle and an + Add referral email action. A separate Referral Routing card below holds the rep-editable Source / Type dropdowns.
  • App chrome matches Command Center — navy sidebar (--sidebar-background: 215 60% 13%) with patients grouped by referral source in collapsible sections, intake date under each name, amber dot for unsaved edits, and the Follow Up section at the bottom; navy gradient topbar with the app tile, "Medically Modern" eyebrow, page title, patient subtitle and the emerald Save button.
  • Request Type is derived, not typed — computed from the product categories + pump need, shown as a chip.
