# Redesign audit — built vs. Brandon's handoff (doc rev 34)

Done 2026-09-18 after Josh: *"all of this is broken / audit everything to his
breakdown / his ui should literally of just been a port to our already perfectly
functional site just combining data."*

He is right about the principle, and it is the standard the column below judges
against: **the redesign is navigation and composition, not new logic.** Where
this build re-derived something the app already does, it broke it.

## The pattern worth naming

Three of the four failures are the same mistake: **a new surface re-derived
something the app already had.**

- the search row re-derived "find this patient's record" → broke on an empty name
- the manager home re-derived "what goes here" → a blank page
- the patient screen re-derives each stage's fields → thin, and the spec asks
  for the real components anyway

Where the build **reused** (the fax lookups, the home views, the stage bars,
`useLiveSearch`) nothing broke. That is the instruction, and it should be the
default for the rest: reach for the existing component, render it read-only,
pass it the patient.
