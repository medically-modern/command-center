- The dark toolbar at the bottom (Sample data / Layout / Viewing as / Old pages / Home / Feature list) is a mockup control only — do NOT build it. Use its "Viewing as" select (#viewAs) to render each person's view when comparing.
- Not in scope: "Layout: current" and the "Old pages" screens (today's app), #/features (internal feature list), and the stage tool pages (/stage/:id) — those stay exactly as they are in the live app.
- To open the same patient in the REAL-DATA mockup as in the app, evaluate in the mockup page:
    PATIENTS.find(p => Object.values(p.boards||{}).some(b => b && String(b.itemId) === '<Monday item id>')).id
  then go to #/patient/<that id>. Example: [patient name and Monday item id redacted — PHI] → #/patient/[id].

SAFETY RULES (these override everything above)
1. Work on a new branch (redesign-pixel-match). Never push to main, never deploy, never run migrations.
2. Presentation only. You may edit components, pages, layout and CSS. Do NOT modify: server/gateway/API code, Monday or RingCentral client code, data-fetching hooks, the functions that build Monday write payloads, column-ID mappings, auth/access config, environment/config files, or package versions. If matching the mockup seems to require changing any of these, STOP and write it in design/BACKEND_NEEDED.md instead.
3. Do not add Monday columns, boards, tables, endpoints or storage. Mockup features with no backend yet (inbox resolutions and required call notes, extra office phones, patient coordinator assignment, Financials figures, anything else you find) get built as UI only, wired to nothing or disabled, and listed in BACKEND_NEEDED.md.
4. Every field that saves today must still save to the same column with the same value after your change. Before editing a screen, list its current reads/writes (component → hook → column ID) in design/DATA_MAP.md; after editing, confirm the list is unchanged.
5. Verification must never write. In the Playwright script, intercept all network requests and abort every non-GET request, every request to the Monday API that contains a mutation, and every RingCentral send/call endpoint. Log anything that was blocked. Never click Save, Send, Add note, Swap, Replace, Resolve/Called/Texted/No action needed, Call, Upload or Match in the live app; only open, switch tabs and scroll.
6. After each screen: run the existing tests and type-check, commit that screen alone, and stop so the diff can be reviewed before moving to the next screen.
7. At the end, open a pull request (do not merge) that includes DATA_MAP.md, BACKEND_NEEDED.md, the side-by-side screenshots and DIFF.md.
